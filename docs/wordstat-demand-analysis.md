# Wordstat: вкладка «Анализ спроса»

«Анализ спроса» открывается первой вкладкой. «Статистика запросов» сохраняет существующую таблицу и экспорт XLSX. Новая вкладка использует общие фильтры проекта, CSS и Recharts из SEO-аналитики. Отдельного экспорта анализа спроса нет.

## Источник и расчёты

Новая независимая витрина `default.yd_wordstat_demand`:

| Поле | Значение |
|---|---|
| `source` | `all`, `device`, `region` |
| `dimension` | пусто, код устройства или название группы IPLAST |
| `feature`, `category`, `phrase` | категория, подкатегория, запрос |
| `date` | первый день месяца; месяцы хранятся строками |
| `count` | частотность, `Nullable(Int64)` |
| `snapshot` | идентификатор опубликованной версии |

Уникальность факта: `source + dimension + phrase + date`. Она проверяется перед публикацией. Новая вкладка читает только ClickHouse. Старая витрина `yd_wordstat_for` не изменяется командой построения новой витрины.

Периоды 1/3/6/12 месяцев сравниваются либо с теми же месяцами прошлого года (`comparison=year_over_year`, по умолчанию), либо с непосредственно предшествующими 1/3/6/12 месяцами (`comparison=previous_period`). Для 12 месяцев режимы совпадают. Режим влияет на общий спрос, карточки разрезов, диаграмму роста и таблицы. Даты обоих периодов находятся в подсказке рядом с конечным месяцем. Рост агрегата считается после суммирования частотностей. Пропуск не равен нулю; дубли не суммируются. При нулевой базе процент отсутствует, статус — «Новый». Нейтральная зона `WORDSTAT_DEMAND_NEUTRAL_PERCENT` (по умолчанию 2) применяется только к сводным карточкам; таблицы «Растущие»/«Падающие» включают все положительные/отрицательные изменения, без порога базы и ограничения числа строк. Сортировка — в заголовках числовых столбцов.

Сезонность рассчитывается за год конечного выбранного месяца, включая текущий год. Как в статистике, для каждого запроса частотность месяца делится на среднюю по загруженным месяцам этого года и округляется до двух знаков; коэффициент группы — среднее коэффициентов запросов. Будущие и отсутствующие месяцы не изображаются нулями. По умолчанию выбираются три элемента с наибольшим процентным ростом; выбранный запрос входит в набор. Количество линий не ограничено. Диаграмма роста включает все элементы с определённым процентом изменения. При нулевой базе процент не определён; в таблице выводится «Новый».

Карточки разрезов используют месячные данные за выбранный период. Доли считаются от общего спроса; число изменения доли сохраняет смысл процентных пунктов, хотя суффикс в интерфейсе убран. Дополнительные показатели родительского уровня и мобильной доли не выводятся. При неполных данных или сумме долей выше 100% структура не показывается как достоверная. KPI и таблицы сохраняют контекст списка. Идентификатор версии защищает от смешивания общего спроса и разрезов при параллельной публикации.

Четыре KPI расположены 2×2 слева, регионы и устройства — справа. Контейнеры графиков и таблиц имеют одинаковую фиксированную высоту; таблицы прокручиваются внутри, графики подстраиваются под контейнер. При загрузке и фильтрации используется общий спиннер проекта. Все подсказки выводятся поверх контейнеров с переносом к свободному краю окна. Фильтры учитывают ширину рабочего контейнера: на небольших настольных экранах период и детализация становятся компактными списками, сохраняя одну строку с кнопкой очистки справа; мобильная ширина допускает перенос.

## Проверка полноты и обновлений

Полный запуск `load_yd_wordstat_api` означает обработку всех трёх источников, а не принудительное повторное скачивание уже проверенных данных. После очистки исходных `yd_wordstat_all`, `yd_wordstat_device`, `yd_wordstat_iplast_api` история запрашивается с января 2018 года до последнего завершённого месяца, даже если checkpoints сохранились. Очистка только витрин не требует повторного скачивания всей истории. Справочники фраз, устройств и групп должны быть заполнены; загрузка должна быть разрешена настройкой `YD_WORDSTAT_V2_LOAD_ENABLED`.

`region_value` — числовой ID региона Яндекса из справочника. `group_fingerprint` — SHA-256 (64 шестнадцатеричных символа) от JSON отсортированного списка числовых IDs конкретной группы IPLAST. Его рассчитывает `build_iplast_groups`, а загрузчик записывает вместе с месячными данными. Вручную подставлять туда ID региона нельзя. Актуальные имена, составы и отпечатки групп находятся в `iplast_groups` результата `inspect_wordstat_data`. При переносе истории отпечаток должен соответствовать именно составу группы, по которому получены эти данные.

`python manage.py inspect_wordstat_data` — диагностика без вызовов API, записи данных и уведомлений. Проверяет последние 24 завершённых месяца: общий спрос, 3 устройства и 7 групп IPLAST, количество уникальных запросов, пропуски, дубли и суммы между PostgreSQL и ClickHouse. Отдельно показывает устаревшие/отсутствующие checkpoints и региональные строки с неактуальным `group_fingerprint`. Команда не приравнивает импортированную историю без checkpoints к подтверждённой загрузке API.

`python manage.py inspect_wordstat_data --deep` дополнительно проверяет сохранённый интервал каждого checkpoint; это много запросов к PostgreSQL. Обе команды только читают данные. Обычный `check_table_health` теперь вызывает базовую диагностику Wordstat; сам Table Health по-прежнему отправляет штатное уведомление. Пока месячная загрузка не закончена, проверка может сообщать о неполноте — наличие строк больше не означает успешную загрузку.

В селекторе доступны только полные опубликованные месяцы выбранной категории. Текущий месяц исключён; при пустом списке нет надписи «Нет завершённых месяцев». Полнота регионов и устройств проверяется отдельно; карточки объясняют отсутствие структуры. Диагностическое поле API `month_coverage` сохраняет сведения о пропусках.

Обе вкладки кэшируются на 24 часа. Анализ спроса использует ключ опубликованного `snapshot`, даты и фильтров; статистика — отдельное поколение ключей. После новой публикации старый кэш недоступен. Полный конвейер отправляет одно событие после построения обеих витрин; при ошибке второй витрины кэш уже изменившейся статистики тоже сбрасывается. Каждая витрина заменяется через staging и `EXCHANGE TABLES`: очистки рабочей таблицы перед загрузкой больше нет. Замена двух таблиц не является общей транзакцией: при ошибке второго этапа первая уже обновлена, а вторая сохраняет предыдущую полную версию.

Вкладки загружаются при первом открытии и сохраняют данные при переключении между ними. Переподключение сокета, возврат к окну и восстановление сети не запускают загрузку. Запрос выполняется при изменении фильтров, ручном повторе после ошибки или новой версии публикации. Новое открытие всей страницы по-прежнему читает серверный кэш, как остальные дашборды; периодического опроса нет. Фильтры сохраняются. `metadata_only=1` возвращает оболочку Wordstat с версией публикации; обычный builder и XLSX-экспорт работают отдельно.

## Построение витрины

Команда меняет только новую витрину ClickHouse. Она не вызывает Wordstat, не расходует API-квоту и не изменяет исходные таблицы PostgreSQL:

```bash
docker exec analytics-django python manage.py sync_wordstat_demand
```

Источники:

1. Общая история — существующие `month_1`…`month_12` и `year` из `default.yd_wordstat_for`, преобразованные в месячные строки.
2. Устройства — сохранённые месячные строки `yd_wordstat_device` в PostgreSQL.
3. IPLAST — `yd_wordstat_iplast_api` в PostgreSQL; берутся только строки с актуальным отпечатком состава группы.
4. Иерархия и действующий список фраз — PostgreSQL `yd_wordstat_ref`; состав групп — `yd_wordstat_ref_iplast`.

Сначала должны быть применены миграции существующего перехода на Wordstat v2. Для этой вкладки новых миграций Django нет. При отсутствии новой витрины интерфейс показывает пустое состояние; для разрезов без истории показывается недостаток данных.

Построение использует общую блокировку загрузчика: нельзя одновременно запускать его с загрузкой API. Не меняйте справочники во время построения. После полной загрузки API витрина обновляется автоматически; отдельные `--source` загрузки её не публикуют.

Публикация: временная таблица → сверка количества строк, количества непустых значений, общей суммы и уникальности ключей → `EXCHANGE TABLES`. Для базы `default` требуется движок `Atomic` или `Shared`; переключение имён атомарно ([документация ClickHouse](https://clickhouse.com/docs/reference/statements/exchange)). При ошибке до переключения прежняя новая витрина остаётся доступной. Это не изменяет прежний механизм публикации старой вкладки.

## Проверка после заполнения

```sql
SELECT source, count(), uniqExact(phrase), min(date), max(date), sum(count)
FROM default.yd_wordstat_demand
GROUP BY source ORDER BY source;
```

В результате команды `rows` и `by_source` должны соответствовать числу строк в ClickHouse. Для выборочных фраз сверить `all` с исходными месячными колонками старой витрины, `device`/`region` — с соответствующими месячными строками PostgreSQL. Проверить 1 и 12 месяцев, границу года, нулевую базу, детализацию, карточки, CSV и вторую вкладку. Само совпадение общих сумм не доказывает правильность каждой строки.

## Как использовать старую историю без повторных API-запросов

Простого копирования всех старых таблиц недостаточно:

- `yd_wordstat_all` и `yd_wordstat_device` сохранились; это не новые модели. Перенести/объединить данные без дублей по фразе, месяцу и устройству.
- Для `yd_wordstat_iplast_api` нужна месячная история семи групп. Старые данные по отдельным регионам предварительно агрегируются по согласованному непересекающемуся составу IPLAST. Нельзя считать отсутствующий регион нулём. История старых групп подходит только при совпадающем составе.
- В IPLAST заполнить `group_fingerprint`, соответствующий текущему составу группы. Без него история не считается актуальной.
- Команда `import_wordstat_regions` импортирует региональный ZIP в IPLAST без перезаписи существующих значений и без создания checkpoints. Порядок проверки, переноса и дозагрузки: [wordstat-region-import.md](wordstat-region-import.md). Не создавайте checkpoints вручную, чтобы скрыть недостающие месяцы.
- Если требуется лишь показать уже сохранённую историю в новой вкладке, отметки API не нужны: достаточно корректных источников и `sync_wordstat_demand`. Это не гарантирует, что последующий запуск API не обновит последние месяцы.

Миграция `0065` удаляет старые региональные таблицы. Переносить/сравнивать их историю нужно по сохранённой копии; обратная миграция данные не восстанавливает.

## Локальные проверки

`python -m unittest tests.test_wordstat_demand tests.test_wordstat_v2` — из `services/backend`, с изолированными тестовыми настройками. Проверки не обращаются к настоящим БД/API. Проверки интерфейса выполняются на синтетических ответах; настоящее серверное наполнение и `EXCHANGE TABLES` нужно проверить после развёртывания.
