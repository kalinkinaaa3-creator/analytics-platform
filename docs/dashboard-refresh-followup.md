# Уточнения по обновлениям дашбордов

## SEO и контекст в Airflow

Задачи запускают существующие команды Django синхронно через docker exec,
как Wordstat. Успех означает завершение команды; ошибка команды передаётся Airflow.
Нужны включённые ENABLE_SEO_ANALYTICS_LOADS / ENABLE_CONTEXT_ANALYTICS_LOADS в Airflow.
Общий лимит DAG сохранён: 4 часа. Это не бесконечное ожидание: при превышении лимита
Airflow завершит задачу. Остановка клиента docker exec сама по себе не гарантирует
остановку процесса внутри контейнера; перед повторным ручным запуском нужно проверить
состояние Django. Существующая блокировка защищает от одновременных загрузок.
Работа на реальном Airflow в этой сессии не запускалась.

## Table Health и выходные

Проверка контекста рассматривает окно до вчера включительно. В воскресенье и
понедельник последняя дата фактов может быть пятницей. В остальные дни требуются
факты не ранее вчера. Проверки успешного планового запуска сегодня, обработанного
окна, ошибок API, обновления справочника и витрин сохранены. Пустое двухнедельное
окно не становится нормой: исключение относится к субботе и воскресенью.

## Wordstat: нулевые результаты и CSV

Уже поддерживается явный ноль count: "0" для конкретного месяца в results.
Пустой results или отсутствие нужного месяца не превращаются автоматически в ноль.
После получения реального ответа можно определить, обозначает ли он отсутствие
спроса или неполноту ответа. Исторические записи в этой сессии не изменялись.

Тестовый запрос для действующего в проекте API v2; сохранить JSON в UTF-8 как body.json:

```json
{
  "phrase": "бак 0.66",
  "period": "PERIOD_MONTHLY",
  "fromDate": "2025-06-01T00:00:00Z",
  "toDate": "2025-06-30T00:00:00Z",
  "devices": ["DEVICE_DESKTOP"],
  "folderId": "<YD_WORDSTAT_FOLDER_ID>"
}
```

```sh
curl --request POST --header "Authorization: Api-Key <YD_WORDSTAT_API_KEY>" --header "Content-Type: application/json" --data-binary "@body.json" "https://searchapi.api.cloud.yandex.net/v2/wordstat/dynamics"
```

Регионы не ограничены. В Windows PowerShell использовать curl.exe.
Схема: https://aistudio.yandex.ru/ru/docs/search-api/operations/wordstat-getdynamics

CSV с восстановленными исходными фактами можно перенести в рабочий PostgreSQL,
если структура и ключи соответствуют текущим таблицам. Для дополнения существующей
таблицы нужен контролируемый импорт через промежуточную таблицу с проверкой ключей
и вставкой/обновлением нужных комбинаций; простой COPY поверх таблицы может дать
дубликаты или ошибку уникальности. Не переносить чужие id и checkpoints вслепую.
После проверки полноты нужно пересобрать витрины ClickHouse. Региональная старая
выгрузка требует преобразования в агрегаты IPLAST: это не прямой COPY в новую таблицу.

«12 месяцев по апрель 2026» — май 2025–апрель 2026. Сообщение о неполном общем
спросе означает отсутствующие/NULL/дублирующиеся месячные факты выбранных запросов
в источнике all в этом интервале. Наличие лишь четырёх месяцев 2026 года само по
себе не является причиной. Эту проверку не меняли.

Превышение суммы разрезов над all больше не блокирует карточки. Числовые доли
по-прежнему рассчитаны относительно all; полоса пропорционально укладывается в
ширину карточки при сумме более 100%. В статистике «Прочее» — арифметическая
разность, которая может быть отрицательной; это объяснено в подсказке.

## Остальные изменения

Дата в заголовках сырья, остатков и ДЗ берётся из максимального date_add
соответствующей подготовленной таблицы PostgreSQL, независимо от фильтра периода.
Это дата загрузки исходных данных, а не максимальная дата хозяйственной операции.
Раньше в заголовок вообще не передавалась дата. Отображение — в московском времени;
версии кэша этих трёх дашбордов увеличены, чтобы прежний ответ с прочерком не остался.

В лидогенерации разрешены будущие полные недели, включая следующий год; сброс
по-прежнему возвращает стандартный период до текущей недели. «Прочие источники»
переименованы и в интерфейсе, и в XLSX-экспорте. Формулы Wordstat добавлены в тултипы
заголовков и двух расчётных строк; сами формулы статистики не изменены.
