# Уведомления, Airflow и пропуски Wordstat

## Уведомления об ошибках

Используется существующая `analytics.services.bitrix_notify.send_bitrix_message`.
Она отправляет сообщение через `im.message.add`, если включён
`ENABLE_BITRIX_NOTIFICATIONS` и заданы `BITRIX_WEBHOOK_URL`, `BITRIX_NOTIFY_USER_ID`.
Теперь проверяется также тело ответа: HTTP 200 с ошибкой Bitrix не считается успехом.
Недоступность Bitrix записывается в журнал и не заменяет исходную ошибку загрузки.

До корректировки уведомления уже присутствовали в API-пайплайнах проектов,
плановых продаж, закупок, остатков/оборачиваемости, дебиторской задолженности,
выручки и Wordstat; CSV-пайплайнах закупок, оборачиваемости и дебиторки;
пайплайнах парсеров, снимков IPrice, проверке здоровья таблиц и остановке процессов.
Наличие уведомления в пайплайне не покрывало все отдельные HTTP-загрузчики.

Добавлены обработчики в следующих путях:

| Источник / операция | Покрытие |
|---|---|
| SEO-аналитика | Ошибка выполнения, запуска фонового процесса, восстановленные зависшие запуски |
| Контекстная аналитика | Ошибка выполнения, запуска фонового процесса, восстановленные зависшие запуски |
| Bitrix24: подразделения, сотрудники, справочники CRM, поля, лиды, история стадий | Общая фиксация ошибки синхронизации; полный запуск и сверка последних лидов; запуск процесса и прерванные синхронизации |
| Лидогенерация | Ошибка пересборки ClickHouse, включая подключение; неожиданная ошибка загрузки плана XLSX |
| Номенклатура и цены из внешнего API | Ошибка загрузчика |
| Плановые продажи CSV | Ошибка пайплайна |
| HTTP-загрузка проектов, закупок, оборачиваемости, дебиторки | Неожиданная ошибка обработки файла/записи/обновления витрины |
| HTTP-загрузка индикаторов закупок, оборачиваемости и дебиторки | То же |
| HTTP-загрузка планов и справочника плановых продаж | То же |
| Префиксы парсера, классификация продукции, справочники Wordstat | Ошибка загрузчика |
| Транспортные затраты, себестоимость, настройки IPrice | Ошибка загрузчика |

Обычные отказы доступа и проверки формы не являются авариями загрузки.
Для Bitrix24 подавлена повторная отправка одной и той же ошибки при её передаче
из загрузчика в команду. Уведомление после транзакции отправляется через on_commit.
Это не очередь гарантированной доставки: при недоступности Bitrix остаётся журнал.
Тесты подменяют HTTP; реальные сообщения при проверке не отправлялись.

## Почему SEO и контекст быстро завершаются в Airflow

Раньше их DAG выполнял короткий HTTP-запрос на запуск. Django запускает отдельный
процесс через Popen и возвращает ответ, не ожидая загрузки. Airflow видит
завершение HTTP-запроса; фактическое выполнение отслеживается в Django RefreshRun.
Поздняя ошибка фонового процесса не меняет уже успешный статус задачи Airflow.
По следующему запросу DAG переведены на синхронный запуск существующих management-команд
через `docker exec analytics-django`, с `--trigger scheduled`. SEO сохраняет
`--window two-months`; контекст — стандартное окно 14 дней. Airflow теперь ожидает
завершения команды и получает её код возврата. Расписание, две повторные попытки
и общий лимит DAG 4 часа сохранены; лимит задачи увеличен до 4 часов.
Флаги ENABLE_SEO_ANALYTICS_LOADS / ENABLE_CONTEXT_ANALYTICS_LOADS теперь действительно
управляют созданием задачи загрузки. До изменения оператор создавался даже при false.
Нужно включить соответствующий флаг в окружении Airflow для запуска загрузки.
Ручное обновление из интерфейса Django по-прежнему запускается в фоне.

Wordstat запускается через `docker exec analytics-django python manage.py load_yd_wordstat_api`.
Команда ожидает завершения загрузки, включая ожидание квоты. Поэтому задача
остаётся running; её execution_timeout — 10 дней.

## Исторические пропуски и устройства

Отсутствующие факты нельзя заменять нулями, распределением годовой суммы или
интерполяцией: это изменит рост, сезонность и доли. Допустимо восстановить точные
исходные значения из резервной копии/выгрузки либо запросить доступную историю API.
Сначала восстанавливается PostgreSQL, затем проверяются ключи, даты и полнота,
после чего пересобирается ClickHouse. Правка только ClickHouse будет потеряна
при следующей публикации. Код заполнения пропусков в рамках этого запроса не менялся.

Проверенная региональная выгрузка содержит полные месяцы до мая 2025 включительно.
С июня 2025 по апрель 2026 в каждом месяце отсутствует одна пара запрос/регион;
май 2026 заполнен частично, июнь–август отсутствуют. Она не содержит устройства.
Инструкция импорта: [wordstat-region-import.md](wordstat-region-import.md).
Для агрегата IPLAST необходим полный состав исходных регионов; недостающий регион
нельзя считать нулём. Историческая дырка за пределами стандартного окна перезагрузки
может потребовать отдельного восстановления.

Устройства проверяются независимо от регионов. Сообщение о неполноте может означать
отсутствующий факт, NULL, дубликат ключа или неактуальную витрину. Тест подтверждает,
что пропуски регионов не скрывают полный набор устройств. Конкретную причину на
сервере установить не удалось: SSH отклонил авторизацию. Проверка без изменения данных:

```sh
docker exec analytics-django python manage.py inspect_wordstat_data --deep
```

Нужно сопоставить покрытие PostgreSQL и ClickHouse по месяцам и источнику device,
затем определить отсутствующие ключи запрос/устройство/месяц. По одной надписи в
карточке нельзя заключить, что отсутствуют все месяцы начиная с указанного.

## Новые правила вкладки

Фильтры сбрасываются при смене вкладки и выходе. Выбор запросов ограничивает весь
отчёт, включая KPI, линии сезонности, круги и таблицы. Кликабельные количества в
карточках выбирают соответствующие запросы. Список месяцев включает последний
опубликованный месяц даже при исторических пропусках; неполные разрезы не выдаются
за полные. При августовской публикации август доступен.

Сезонность текущего года ограничена опубликованными месяцами этого года. Убраны
год и поясняющий тултип заголовка; подсказка со значениями при наведении на график
сохранена. Более ранние правила сохранения фильтров и выбора только полностью
согласованных месяцев заменены этими требованиями.
