# iPrice Селект Маркета — состояние внедрения

Актуальное состояние на 14.10.2026, проверки и порядок переноса:
[IPRICE_RELEASE_READINESS.md](IPRICE_RELEASE_READINESS.md).
Ниже сохранена история этапов; отметки «пока не подключено» относятся к датам этих этапов.

## Согласованные правила

- Существующая схема `select_market`, отдельные данные от Ай-Пласта.
- Код 1С текстовый и соответствует SKU СПС; преобразование к числу запрещено.
- Полный Excel-прайс всех регионов за одну дату, цены без НДС.
- Отдельный YML каждой организации через окружение; конкуренты прежние.
- Структуры остальных источников и права как в iPrice Ай-Пласта.
- Активация внутри системы и экспорт, без передачи в 1С.

## Реализовано на первом этапе

- `select_market.nomenclature_price` и метаданные полного прайса.
- GET `/api/v1/select-market/iprice/price-file/`: XLSX-шаблон.
- POST на тот же адрес, multipart `file`: загрузка полного прайса.
- Проверка доступа к СУЦ выбранной организации; запись только редакторам.
- Проверка файла до записи, атомарная замена даты, блокировка организации,
  контроль повторной загрузки, текстовые коды и проверка дублей.
- Выбор последнего полного прайса не позднее даты расчёта без индивидуального
  возврата к старой цене отсутствующего товара.
- Предыдущие даты сохраняются. Повторная публикация той же даты заменяет строки;
  метаданные содержат только последнюю загрузку и номер ревизии.

## Второй этап: изолированное хранилище и общие выборщики

- Добавлены 24 модели источников, настроек, расчётов и аудита, а также 5 моделей
  состояния ТАРА. Все таблицы явно расположены в `select_market`; внутренние FK
  ведут в эту же область. Связи с пользователями остаются общими.
- Код номенклатуры текстовый также в справочнике, себестоимости, YML-данных и
  строках расчёта. Идентификаторы строк парсеров остаются числовыми.
- `datasets.services.iprice_workspace` выбирает модели явно, по разрешённой
  организации. Глобального изменения моделей или `search_path` нет.
- Общие функции `iprice_source_selector` принимают `workspace`; прежние вызовы
  Ай-Пласта сохраняют прежнее поведение. Прайс Селект Маркета выбирается целиком.
- Модели описаны статически, без наследования от конкретных моделей Ай-Пласта;
  расчётные алгоритмы не копируются. Изменения контрактов нужно сверять между
  двумя наборами моделей. Это ещё не подключение всех сервисов и команд.
- Изолированные тесты проверяют обе организации одновременно, включая совпадающие
  ID парсеров, раздельные цены конкурентов, регионы и себестоимость.

## Ограничение нагрузки парсеров — обязательное условие включения

До подключения запуска Селект Маркета нужен общий серверный диспетчер:

- Один активный полный сбор для обеих организаций; остальные запросы ожидают FIFO.
- Общая координация через PostgreSQL, а не блокировка только кнопки или процесса.
- Владение слотом сохраняется в `waiting_tara` и `waiting_session`: основной
  процесс в этот момент может завершиться, но удалённый сбор ещё не завершён.
- Все входы (API, команды, Airflow, ручной ТАРА и возобновление) используют один
  механизм; отдельный запуск источника не должен обходить ограничение.
- Повтор запуска не создаёт второй активный сбор той же организации.
- Истечение таймера само по себе не разрешает параллельный запуск: сначала
  подтверждается остановка предыдущего исполнителя, с защитой от старого владельца.
- Статус API должен показывать очередь и причину ожидания; секреты не публикуются.

### Реализованное ядро очереди

Общие модели `datasets.ParserQueueCoordinator` и `ParserQueueEntry` хранят очередь
обеих организаций. `datasets.services.parsers.global_queue` реализует:

- FIFO и идемпотентный запрос по организации, виду задания и ID запуска;
- транзакционную выдачу слота под блокировкой строки PostgreSQL и дополнительное
  ограничение БД на единственный занятый ресурс;
- сохранение слота при ожидании удалённого исполнителя;
- смену токена при возобновлении и отказ от запоздалых изменений старого владельца;
- отмену только ожидающего задания своей организации;
- диагностический статус без раскрытия задания другой организации и токена;
- перевод зависшего задания в `recovery_required` без автоматического освобождения.

### Подключение исполнителей (выключено по умолчанию)

`PARSER_SHARED_QUEUE_ENABLED=1` включает адаптеры действующего контура Ай-Пласта:

- регистрация мастер-запроса до старта процесса, FIFO при допуске к выполнению;
- удержание слота мастер-процессом и его этапами без повторного захвата;
- допуск удалённого ТАРА только в слот родительского мастера или собственный слот;
- отдельные вызовы YML, PS, TT, ТАРА, ссылок и изображений отказывают при занятом
  ресурсе; ручные синхронные команды не ставятся в бессрочное ожидание;
- периодический `process_tara_jobs` повторно запускает ожидающий головной мастер;
- сердцебиение исполнителя и запрет автоматического перезапуска по одному таймеру;
- сведения об ожидании в API и React действующего iPrice.

Флаг по умолчанию **выключен**: миграция и конкурентные PostgreSQL-тесты должны
предшествовать включению. Адаптеры пока работают с контуром Ай-Пласта; Селект
Маркет не получает возможность запуска до адаптации его расчётной цепочки.

Перед включением: применить миграции, дождаться завершения всех старых мастер-
процессов, отдельных команд и удалённых запросов ТАРА, остановить новые запуски
на время переключения, включить флаг согласованно во всех backend/worker/CLI
окружениях, проверить периодический `process_tara_jobs`. Нельзя смешивать процессы
с включённой и выключенной защитой. Рабочий сервер автоматически не переключается.

`recovery_required` сохраняет блокировку. Автоматического снятия нет.
Фоновый процесс с аварийным завершением намеренно не передаёт слот следующему.

### Восстановление оператором

1. Остановить запуск новых заданий и подтвердить завершение/остановку всех
   процессов данного сбора, включая удалённый Windows-исполнитель и запросы ТАРА.
   Одна старая дата heartbeat или статус «отменён» не доказывают остановку.
2. Просмотреть состояние: `python manage.py recover_parser_queue ENTRY_ID`.
   Без `--release` команда только читает данные. Сохранить выведенный fingerprint.
3. Выполнить `python manage.py recover_parser_queue ENTRY_ID --release
   --workers-confirmed-stopped --fingerprint FINGERPRINT --operator OPERATOR
   --reason "Причина и выполненные проверки остановки"` (одной строкой).
4. Команда проверяет неизменность состояния, завершает незавершённые связанные
   задания ошибкой, отзывает lease и токены удалённых запросов, сохраняет оператора
   и причину в `recovery_audit`. Старое задание не запускается заново автоматически.
5. Возобновить периодический диспетчер и при необходимости создать новый запуск.

Команда не останавливает ОС-процессы сама: флаг подтверждает выполненную оператором
проверку. При новом heartbeat после просмотра восстановление отклоняется.

## YML Селект Маркета

`python manage.py load_select_market_catalog` использует общий `base_parser` с
явным `IPriceWorkspace("select-market")`, а не отдельную копию алгоритма.
Требует включённой общей очереди; при занятом слоте прекращается до HTTP-запроса.

- URL задаётся `SELECT_MARKET_IPRICE_YML_URL`, для Ай-Пласта — `IPLAST_IPRICE_YML_URL`.
  Пустое значение блокирует загрузку; встроенных приватных адресов нет.
- Текстовый «Код товара» сохраняется без преобразования в число; числовой offer ID
  пока соответствует исходному формату YML Ай-Пласта.
- Из исходной цены вычитается НДС по прежнему правилу этого YML (22/122).
- Пустой каталог, некорректные позиции, отсутствующие коды и дубли URL отклоняются.
- Изменения каталога и цен публикуются одной транзакцией. При ошибке всё откатывается.
- `--limit N` не помечает необработанные товары неактивными. Полная выгрузка
  помечает отсутствующие URL неактивными только в схеме Селект Маркета.
- Проверяется точное совпадение кодов с Product.sku СПС; результат содержит числа
  совпавших/несовпавших кодов. Автоматического создания мастер-товаров нет.
- Ссылки изображений сохраняются из YML. Скачивание в отдельный локальный кеш
  Селект Маркета пока не подключено; кеш и события коммерческого прайса Ай-Пласта
  эта загрузка не обновляет.

Контрактные тесты очереди выполняются без внешних запросов. Тест одновременного
захвата двумя процессами/соединениями требует PostgreSQL и на SQLite пропускается.

## Следующие этапы

### Завершённая адаптация загрузок источников

GET `/api/v1/select-market/iprice/sources/<kind>/` выдаёт XLSX-шаблон;
POST на тот же адрес принимает multipart `file`. Поддерживаются `product_cost`,
`transport_cost`, `calculation_config`, `parser_prefixes`, `product_classification`.
Чтение доступно зрителям СУЦ, загрузка — редакторам выбранной организации.

- Общие загрузчики принимают workspace, прежние вызовы Ай-Пласта сохраняются.
- Себестоимость заменяется полностью; транспорт и параметры сохраняют версии
  изменений по прежним правилам iPrice. Коды себестоимости остаются текстовыми.
- Префиксы заменяются только в выбранном контуре. Классификация и автоматические
  аналоги пересчитываются с сохранением ручных связей и исключений.
- Региональные группы конкурентов и ссылки изображений выбираются из таблиц
  Селект Маркета. Неизвестные/неактивные ID в классификации отклоняют весь файл.
- Проверяются структура XLSX, формулы, лимиты размера, точность чисел и длины полей.
  Запись и журнал импорта выполняются атомарно под блокировкой организации.
- `IPriceSourceImport` сохраняет исходный файл, checksum, пользователя и результат
  каждой успешной загрузки (миграция `0005_ipricesourceimport`). Это журнал этих
  пяти источников, ещё не полный снимок всех данных расчёта.
- React-формы этих загрузок пока не подключены. Реальные источники не запускались.

Проверка: 61 тест прошёл, один тест конкурентного захвата очереди пропущен
на SQLite и требует PostgreSQL. Миграции на рабочем сервере не выполнялись.

### ТопТара: отдельные таблицы, общий исполнитель

Команда `python manage.py load_select_market_tt --sync-links` собирает ссылки,
цены и свойства ТопТара через существующие алгоритмы с workspace Селект Маркета.
Без `--sync-links` обрабатывает имеющиеся активные ссылки. Поддерживает `--limit`
и `--workers` (по умолчанию один, максимум четыре). Реальный сбор не запускался.

- Общая очередь должна быть включена; занятый слот отклоняет запуск до HTTP.
  Ссылки, цены и синхронизация изображений удерживают один слот до завершения.
- Workspace явно передаётся рабочим потокам; цены, свойства, ошибки и статусы
  URL изменяются только в выбранных таблицах. Изображения не скачиваются в кеш.
- Пустой набор ссылок или ошибка получения вариантов товара откатывает изменения
  ссылок Селект Маркета. Это не доказательство полноты HTML-каталога источника:
  ограничения пагинации и распознавания страниц остаются правилами общего парсера.
- Цены сохраняются транзакцией на товар. Ошибка части товаров не удаляет успешные
  результаты, но команда завершается ошибкой и общий запуск получает failed.
- Старые вызовы без workspace продолжают использовать таблицы Ай-Пласта.
- Отдельная команда пока не подключена к React. Мастер-процесс использует этот
  же парсер для товаров из активной классификации.

### Оставшаяся работа

Транспортное ядро ТАРА принимает явный workspace в fetch/claim/complete.
Задания, run lease и ответы изолированы по схеме; состояние физического Windows-
исполнителя и координатор его выдачи намеренно остаются общими в datasets.
При включённой очереди лимит пяти выданных запросов учитывает обе схемы.
Селект Маркет обязан владеть общим слотом при запросе/выдаче/приёме результата.
Сохранение цен, свойств и ошибок ТАРА также допускает отдельные модели.

Диспетчер `tara_jobs` теперь принимает workspace: создание, выбор товаров,
сохранение результатов, ожидание, повторная попытка и завершение используют
отдельные таблицы. Команда `process_tara_jobs` обслуживает обе организации при
включённой общей очереди. Для отдельного сбора Селект Маркета:

`python manage.py load_select_market_tara --request-key UNIQUE_KEY --sync-links`

Поддерживаются `--limit` и `--workers` (по умолчанию 1, максимум 5). Одинаковый
request-key возвращает тот же запуск; для нового обхода нужен новый ключ.
Без `--sync-links` используются имеющиеся ссылки. Перед реальным запуском
обязательны миграции, проверка PostgreSQL и согласованное включение общей очереди.

Worker API выбирает организацию по занятому слоту, а результат маршрутизирует
по паре ID + случайный токен задания. Формат запросов Windows-клиента не меняется.
Запросы страниц привязаны к ID запуска и lease; устаревший процесс не сохраняет
результаты в новый запуск. Sitemap также проверяет lease перед записью ссылок.
Ожидание исполнителя удерживает слот; истёкшее ожидание освобождает только
припаркованный слот, но не running/recovery_required. Дедлайн ожидания не продлевается.

Для Селект Маркета уведомления пока пишутся только в журнал: канал Bitrix и
события React Ай-Пласта не используются. Организационные события подключаются
вместе с React. ТАРА также подключена к общему мастер-конвейеру, описанному ниже.
Удалённый исполнитель, реальные сборы и рабочий сервер в этом этапе не запускались.

PS также адаптирован: `python manage.py load_select_market_ps --sync-links`.
Параметры и общая блокировка аналогичны ТопТара; оба используют сервис
`select_market.iprice_competitors`, без копии управления запуском.
Региональные префиксы, URL, цены, свойства и статусы берутся из select_market.
Ошибка страницы каталога, пропущенный регион или пустой региональный каталог
прерывают обновление ссылок с откатом. HTTP 404 на последующих страницах остаётся
признаком конца пагинации по контракту существующего парсера; полноту сайта
это само по себе не гарантирует. Старый контур сохраняет прежние правила.

После подключения PS: 77 тестов прошли, один PostgreSQL-тест пропущен на SQLite.
Сетевые обращения в тестах заменены заглушками; реальные сборы не запускались.

1. Полный неизменяемый журнал ревизий файлов и снимки источников расчётов.
2. PostgreSQL-проверка очереди и остальные адаптеры исполнителей Селект Маркета.
3. Подключение остальных общих сервисов с явно переданным набором моделей, источниками и организацией;
   отдельные кеши, задания, блокировки, файлы и события.
4. Организационные события и отдельный кеш изображений.
5. Расчёты, корректировки, активация и выгрузки изолированного контура.
6. React из архива через авторизацию и оболочку платформы, без второй авторизации.
7. Проверка на PostgreSQL: миграции, параллельные загрузки и независимость Ай-Пласта.

## Общий мастер-конвейер Селект Маркета

`python manage.py start_select_market_parsers` создаёт запуск и ставит его в
общую очередь. Повтор команды при незавершённом запуске возвращает тот же запуск.
Последовательность и сохранение этапов используют существующий `master_pipeline`;
адаптер `select_market.iprice_pipeline` вызывает общие сервисы с workspace.

- Полный YML → ТопТара → PS → ТАРА → повтор только ошибок ТАРА.
- Конкуренты выбираются из активной классификации, как в мастере Ай-Пласта.
  Первичная загрузка ссылок выполняется отдельными командами до классификации.
  Пустая классификация означает нулевой набор, а не обход всего сайта.
- Слот удерживается при ожидании ТАРА. Завершённые этапы пропускаются при
  возобновлении; результаты источников сохраняются в `run.result`.
- Команды отчётов Ай-Пласта не запускаются. Их места в последовательности
  фиксируют наличие результатов в запуске; отдельные файлы отчётов ещё не создаются.
- Сбор с ошибкой PS/ТопТара останавливается. Ошибки первого прохода ТАРА допускают
  повтор; оставшиеся ошибки второго прохода завершают запуск с ошибкой.
- Периодический диспетчер запускает и возобновляет мастера нужной организации.
  Журналы и файловые блокировки мастеров имеют отдельные имена для Селект Маркета.
- Восстановление после аварии продолжает требовать проверки остановки процессов;
  статус или истечение heartbeat не разрешают автоматически освобождать слот.
- Запуск из React и организационные события остаются следующим этапом.

Проверены 95 тестов, один конкурентный тест требует PostgreSQL. Внешние источники
и создание процессов в тестах заменены заглушками. Реальные сборы не запускались.

## React: источники и управление загрузками

Приватная страница существующего компонента `suc` подключена к
`SelectMarketIPrice`. Используются авторизация, выбор организации и API-клиент
платформы; отдельный вход не добавляется. Публичный маршрут не подключается к
новым API. Стили ограничены `.sm-iprice` и используют токены Селект Маркета.

- Шесть XLSX-источников: полный прайс, себестоимость, транспорт, префиксы,
  классификация и параметры. Шаблоны доступны зрителям; запись — редакторам.
- История последних файлов, состояние мастера, текущий этап и собственная очередь.
  Состояние обновляется каждые 5 секунд; запрос опроса отменяется при уходе.
- GET `status/` проверяет доступ к СУЦ выбранной организации и не возвращает
  исходные файлы, токены исполнителя или внутренний traceback.
- POST `parsers/start/` разрешён только редактору и только при включённой очереди.
  Сначала создаётся постоянная запись очереди; запуск подхватывает диспетчер.
  Повторное нажатие возвращает тот же незавершённый мастер.
- Расчёт, утверждение, выгрузки и остальные экраны из архива руководителя ещё
  не подключены. Этот этап закрывает только источники и запуск сбора.

Проверка этапа: 100 тестов backend прошли, один требует PostgreSQL. ESLint
изменённых React-компонентов и production-сборка прошли. Vite предупреждает
о размере общего bundle. Проверка интерфейса в браузере с рабочим API ещё нужна.

## Расчётное ядро: отдельные версии, общие формулы

`iprice_snapshot_builder` принимает workspace при создании расчёта; далее
хранилище определяется по модели snapshot. Формулы не копируются. Продукты,
аналоги, региональные строки, версии и переключение текущей/активной версии
используют таблицы выбранной организации. Коды 1С остаются текстовыми.
Выбор цен использует последний полный Excel-прайс, а не индивидуальный откат
к прошлой цене отсутствующего товара. Уведомления и события Ай-Пласта не вызываются.

Для Селект Маркета создание версии блокирует строку организации и отклоняет
второй незавершённый расчёт. Неудачная ревизия не снимает предыдущую текущую
версию. Ошибки отдельных строк сохраняются явно; статус success версии сам по
себе не означает отсутствие ошибок строк — это прежний контракт iPrice.

Сквозные тесты проверяют текстовый код, себестоимость с логистикой, текущий прайс,
ошибки отсутствующих данных, сохранение предыдущей версии и независимость
активной версии Ай-Пласта. Всего 106 тестов прошли, один требует PostgreSQL.

Это подключение ядра, не завершённый пользовательский расчёт: ещё нужны источник
справочника Nomenclature (включая quantity_eurotruck), согласованный снимок входных
данных при параллельных загрузках, фоновый запуск/API, экраны расчёта, права и
проверки утверждения, выгрузки. Функция внутреннего переключения активной версии
ещё не предоставлена через API. Передачи в 1С нет. Рабочий сервер не менялся.

## Excel-номенклатура и просмотр расчётов

По подтверждению пользователя номенклатура на первом этапе поступает отдельным
XLSX. Новый источник `sources/nomenclature/` использует тот же контроль прав,
лимитов, транзакцию, блокировку организации и журнал исходных файлов.
Шаблон: `nom_code, nom, nom_view, nom_category, nom_group, nom_hier, quantity_eurotruck`.
Код текстовый, наименование обязательное, вместимость — положительное целое
или пустое значение. Дубли, формулы и некорректные значения отклоняют весь файл.
Коды из файла обновляются, остальные сохраняются; пустые поля очищают прежние
значения. СПС-товары и таблицы Ай-Пласта не изменяются.

React подключает этот источник и просмотр последних 50 версий расчёта.
GET `snapshots/` и `snapshots/<id>/rows/?page=N` доступны зрителям СУЦ;
региональные строки возвращаются по 50, без внутренних параметров/traceback.
Текстовый код, регион, производство, текущая цена, себестоимость с логистикой,
расчётная РРЦ и ошибки видны в таблице. Запуска расчёта и утверждения в UI пока нет.

Для изменённого контура прошли 30 backend-тестов, ESLint и production-сборка.
Предупреждение Vite о размере общего bundle сохраняется. Миграции не добавлялись;
браузерная и PostgreSQL-проверки остаются отдельными этапами.

## Фоновый расчёт из React

POST `calculations/start/` доступен только редактору СУЦ Селект Маркета. Принимает
`calculation_date` (обязательная дата, не позднее текущей), создаёт версию и
запускает обработчик после commit. Повтор до завершения предыдущей версии
отклоняется. Ошибка запуска процесса переводит созданную версию в failed.

Общий `iprice_snapshot_launcher` запускает для Селект Маркета команду
`build_select_market_snapshot --snapshot-id ID` с отдельным именем журнала.
На PostgreSQL обработчик использует REPEATABLE READ и транзакционный advisory
lock на расчётный контур Селект Маркета. Источники читаются в одном состоянии БД;
это не полный архив исходных файлов и не гарантия завершённости текущего сбора
парсеров. Строки новой версии публикуются одной транзакцией. При ошибке частичные
строки откатываются, затем отдельно фиксируется failed; прежняя текущая версия
сохраняется. Повтор команды для завершённой версии не пересчитывает её.

React показывает форму даты и запуска только редакторам, обновляет список версий
раз в 5 секунд и обновляет таблицу выбранной версии при смене статуса. Авторизация
и выбор организации остаются общими. Нет автоматического утверждения или отправки в 1С.

При аварийном завершении ОС-процесса версия может остаться building: таймер сам
не снимает защиту и не создаёт второй расчёт. Проверка процесса и восстановление
остаются задачей администратора; автоматический диспетчер восстановления ещё
не добавлен. Прямые Python-вызовы расчётного ядра не заменяют этот worker-протокол.

Проверены 17 тестов расчёта/API, ESLint и production-сборка React. PostgreSQL-
изоляция и конкурентный запуск требуют отдельного стенда; SQLite этого не доказывает.
Рабочий сервер, фоновые процессы и реальные расчёты в этом этапе не запускались.

Миграция подготовлена, на рабочем сервере не выполнялась. SQLite-тесты проверяют
валидацию и атомарность, но не доказывают работу блокировок PostgreSQL.
