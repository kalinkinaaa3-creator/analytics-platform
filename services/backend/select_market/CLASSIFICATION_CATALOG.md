# Неклассифицированные товары и полный сбор Селект Маркета

После обновления backend выполнить миграцию `select_market 0017_classification_editor`.
Она добавляет источник ручной классификации и историю изменений; существующие
классификации обозначаются как загруженные из Excel. Миграция не применялась агентом.

В карточке товара доступна вкладка «Неклассифицированные товары». Она показывает
актуальный каталог, а не срез на дату открытого расчёта. Поиск работает по последнему
названию и URL; товары без загруженного названия можно найти по URL. Региональные
страницы объединяются по нормализованному URL с учётом настроенных префиксов.
Разные additional_property не объединяются. Отсутствующий регион показывается «—».

Цена берётся за последний день сбора каждой позиции: положительные варианты
сводятся медианой, затем вычисляется медиана региона и медиана по регионам.
Нулевые/отсутствующие цены не участвуют. Даты и ссылки доступны по регионам.
Наличие цены не является условием сохранения классификации.

В проверке исходных данных отсутствие цены аналога не является замечанием.
Проверяется только непустой last_error активного классифицированного аналога,
который соответствует региону товара и не исключён пользователем. Неактивные
ссылки и ещё не загруженные позиции без ошибки не создают замечаний.
Успешный сбор с is_loaded=True и пустым last_error считается нормальным,
даже если положительная цена не найдена. Старая цена не скрывает ошибку нового сбора.

Классификация сохраняется для всех ключей карточки с проверкой изменения её состава.
Автоматические связи обновляются по тем же признакам, что при импорте Excel;
ручные включения/исключения сохраняют приоритет. Ранее сохранённые расчёты не меняются.
Цены новой классифицированной позиции обновятся при следующем штатном сборе.

Excel сохраняет прежние правила полной загрузки: заменяет переданные значения,
снимает активность отсутствующих строк с прежними исключениями для ручных аналогов
и неактивных собственных товаров. Источник обновлённой из файла строки — «Загрузка Excel».
Источник строки из карточки — «Интерфейс». История действий интерфейса сохраняется
после импорта. Лист «Действующая классификация» в готовности к расчёту включает
все активные строки, независимо от способа ввода, со столбцом «Источник классификации».

## Ручной DAG

`select_market_competitors_full` не имеет расписания (`schedule=None`).
Единственный reschedule-sensor создаёт устойчивое задание и наблюдает этапы:
ТОПАЗ (ссылки → карточки) → ПЛАСТИК СИСТЕМ (ссылки → карточки) → ТАРА
(sitemap → карточки → повтор ошибок). Собственный YML-каталог не затрагивается.
Все активные товары доступны сбору независимо от классификации; успешно обновлённые
сегодня позиции могут быть пропущены существующими парсерами.

Нужны включённая общая очередь `PARSER_SHARED_QUEUE_ENABLED`, одинаковый
`INTERNAL_API_KEY` в Airflow/backend и работающий штатный диспетчер ТАРЫ/мастеров
с Windows-исполнителем. DAG не обходит очередь Ай-Пласта и не меняет его таблицы.
При занятости очередь ожидается без расходования retry. Ожидание ограничено
7 сутками Airflow; остановка sensor не освобождает слот работающего парсера.
Нельзя вручную освобождать слот без проверки завершения исполнителя.

Airflow `run_id` служит ключом идемпотентности. Повторные опросы/очистка task
наблюдают прежнее задание, в том числе его итоговую ошибку. Для нового полного
сбора после ошибки нужен новый DAG run. Ошибка этапа останавливает следующие этапы.
В логе sensor видны ID, статус, текущий этап и результаты завершённых источников.

Существующий `select_market_base_parser_pipeline` продолжает работать отдельно.
Его прежнее поведение UP_FOR_RETRY при занятом общем слоте не изменено.


## Выбор классификации в интерфейсе

Поля расположены по одному в строке. Можно выбрать только целое сочетание из
действующей классификации, загруженной из файла (manual_edit=False). Списки
взаимозависимы; ввод произвольного значения запрещён также на сервере.
После сохранения обновляются рынок категории и список конкурентов. Новый
автоматический аналог показывается с отметкой «для следующего расчёта»:
сохранённый состав расчёта, его цены и ручные утверждения не переписываются.
История последних 50 изменений открывается справа кнопкой «История классификации».

В фильтрах «Модификация» остаётся modification; ниже добавлена «Группа аналогов»
(article_number_analogs). В карточках выводится article_number_analogs вместо
modification. Миграция 0018_snapshot_analog_modification фиксирует новое поле
в снимке расчёта. Старые снимки заполняются из доступной на момент миграции
классификации; историческое значение группы аналогов восстановить невозможно.
Миграция не применялась агентом.

## Ручной перенос свойств и цен из Ай-Пласта

В sql/export_unclassified_moscow_from_iplast.sql — четыре SELECT без id для CSV:
свойства, Тара, Пластик Систем, Топаз. Источник предполагается в public в той же БД.
По подтверждению пользователя product_key конкурентов совпадает и сохраняется.
Московские префиксы берутся из parser_prefix.shipp_region (регион «Москва»);
для Топаза ограничение префикса отсутствует. Действующая классификация проверяется
в select_market. Уже присутствующие идентичные строки не выгружаются.
Импортировать CSV в соответствующие таблицы select_market, не заполняя id.
После импорта — sql/reset_imported_parser_sequences.sql. Запросы не запускались.
