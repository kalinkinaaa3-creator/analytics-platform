# Витрина сделок

`default.bitrix_deal_analytics` — самостоятельная таблица ClickHouse с аналитическими
записями сделок. Названия менеджеров, подразделений, источников, воронок и стадий,
порядок сортировки воронок и стадий, даты и рассчитанные длительности находятся
в самих записях. Персональное отслеживание по-прежнему применяется при запросе;
пользовательские настройки не переносятся в общую витрину.

Фильтры получают справочные значения из опубликованных записей за весь период
витрины и затем ограничивают варианты по взаимосвязанным фильтрам. Отдельная
таблица `bitrix_crm_references` для новой витрины не используется.

## Первое обновление

После установки нового кода выполнить из каталога backend:

```console
python manage.py sync_bitrix24_clickhouse
```

Команда использует уже загруженные локальные данные CRM. Она также обновляет
витрину лидов и связанные отчёты согласно существующему порядку обновления.
Обычное полное обновление CRM тоже публикует новую витрину сделок.

До первой публикации код умеет читать прежние `bitrix_crm_entities` и
`bitrix_crm_references`. При публикации сначала заполняется временная таблица
и проверяется число записей. Старое представление `bitrix_deal_analytics`
заменяется таблицей только после подготовки данных. Последующие обновления
используют `EXCHANGE TABLES`; предыдущая витрина доступна во время подготовки.

Идентификатор публикации находится в поле `snapshot` и комментарии таблицы.
Комментарий позволяет корректно читать и пустую опубликованную витрину.

## Проверка и удаление старых таблиц

Проверить в ClickHouse:

```sql
SELECT name, engine, comment
FROM system.tables
WHERE database = 'default' AND name = 'bitrix_deal_analytics';

SELECT count(), uniqExact(entity_id), uniqExact(snapshot)
FROM default.bitrix_deal_analytics;
```

Ожидается `engine = 'MergeTree'` и непустой комментарий, а не `View`.
Число записей должно совпадать с числом уникальных ID сделок; для непустой
витрины должна быть ровно одна версия `snapshot`. Сверить результат с числом
неудалённых сделок в локальной CRM на момент обновления. Проверить отчёт,
фильтры, попапы и экспорт, включая персональное отслеживание и пустые источники.

После успешной проверки и переключения всех экземпляров backend старые
таблицы больше не нужны приложению. Перед удалением также проверить внешние
отчёты или ручные SQL-запросы, которых нет в этом репозитории. Удаление выполняется
отдельно и не запускается автоматически при обновлении:

```sql
DROP VIEW IF EXISTS default.bitrix_full_cycle_analytics;
DROP TABLE IF EXISTS default.bitrix_crm_references;
DROP TABLE IF EXISTS default.bitrix_crm_entities;
```

После этого возврат к прежней версии приложения потребует восстановления
старых витрин. Новая версия продолжает работать только с `bitrix_deal_analytics`.
